## Observations (outside the agreed criteria, not failures)
Nora records what she saw. None of these breaks an acceptance criterion as written; they are for the owner to route.
- **O1 — impossible calendar dates pass the shape check.** `sanitizeCapitalEvents()` (iteration 1 code) accepts any `YYYY-MM-DD` shape. An event stored or imported with `date: "2026-13-99"` is kept. Observed: the row reads `99/13/26 Capital $5000,00 Ajuste +$700,00 1R $50,00`, `currentCapital()` becomes 6040 (the +700 is counted) while `oneRValue()` stays 50 (the rebase has no effect on today's 1R), and there is no page error. The agreed `NEG3` example is `"2026-13-99x"`, which is discarded as required. Only a hand-edited file or storage can produce this; the app itself never writes such a date. Whether "fecha mal formada" in the checklist should also cover impossible dates is a requirements decision.
- **O2 — duplicate ids.** Two stored or imported events with the same `id` are both kept. Observed: with two events with id 60, one call to `deleteCapitalEvent(60)` removed both (2 before, 0 after). The app itself creates strictly increasing ids, so only a hand-edited file can produce this.
- **O3 — screenshot noise in the working tree.** `dialog-1280.png`, `dialog-390.png`, `initial-modal-1280.png` and `initial-modal-390.png` (iteration 2) show as modified in `git status`, but their pixel data is identical to HEAD; only the per-sync `caBX` provenance chunk changed. They are not part of this iteration's work and are left out of the commit.
